Target net10.0. Namespace and assembly Steppewise. Single ASP.NET Core project src/Steppewise/Steppewise.csproj with explicit NuGet <PackageId>Steppewise.Workflows</PackageId> and OpenTelemetry ActivitySource("Steppewise"). Component boundaries: runtime core (Runtime.cs, Contracts.cs, ControlGate.cs, project dependencies, persistence, and verification), HTTP/browser presentation (Program.cs and wwwroot/), and repository packaging (examples/, scripts/, docs/, README.md, and qualification commands).
Public runtime API: sealed class WorkflowRuntime(string storageRoot); Task<RunSnapshot> StartAsync(string workflow, CancellationToken ct = default); Task<RunSnapshot> ReviewAsync(string id, bool accept, string expectedHash, CancellationToken ct = default); RunSnapshot Get(string id); IEnumerable<RunSnapshot> List();
Records: RunSnapshot(string Id,string Workflow,string Status,int Version,string EvidenceMode,List<RunEvent> Events,List<Artifact> Artifacts); RunEvent(int Sequence,DateTimeOffset Timestamp,string Action,string Boundary,string Status,string Detail); Artifact(string Id,string Hash,string Json,bool Passed,string Detail).
Workflow IDs service-intake (synthetic change-request ticket CR-1042, step boundary request.intake, rollbackPlan verification) and local-ai-work. Status Running/AwaitingReview/Accepted/Rejected/Failed. EvidenceMode fixture. Each preserves failed and repaired artifacts. Real MAF execution mandatory. No local inference or hardware actions. Review hash must match latest artifact, checks pass, pending state. Thread-safe serialized operations. Durable persistence must disclose exact recovery capabilities; do not claim multi-host support without implementation and verification.
HTTP API presentation: GET /api/runs; POST /api/runs/{workflow}; GET /api/runs/{id}; POST /api/runs/{id}/review body {accept,expectedHash}. Explicit STEPPEWISE_ENV dev|qa|prod required (along with STEPPEWISE_PORT, STEPPEWISE_STORAGE, STEPPEWISE_DEFINITIONS, STEPPEWISE_EMIT_TRACE, STEPPEWISE_FAULT_MARKER, STEPPEWISE_FAULT_AFTER, STEPPEWISE_FAIL_REPAIR, and STEPPEWISE_FAIL_REVIEW). UI localhost only by default; no authentication claims. User sees fixture disclosure, failed check, repair, human review and persona projections. Commands returning exceptions map to non-200 errors.
Breaking storage compatibility: evidence directories created before the v2 rename are refused on startup by ValidateSnapshot (ValidateSnapshot refuses the retired pre-rename workflow id via !definitions.ContainsKey(s.Workflow)). Always point STEPPEWISE_STORAGE at a fresh v2 evidence directory.
Scope progression: runnable vertical slice first, then qualify persistence/fencing, declarative graphs, A2A and offline controller. Unimplemented capabilities must be explicitly pending. No source copied from private production. No production changes, GPU dispatch, public publication or demo edits.

Review revision: RunEvent adds optional int? CauseSequence=null (backward compatible). Domain progression references the preceding domain event; raw MAF arrival events have no causal claim.

## Additive traceability and message contracts
RunEvent retains its original fields and adds nullable TraceId, SpanId, Actor, ActorSource and DecisionId after CauseSequence. ReviewAsync retains its original overload and adds an optional reviewer-name overload; POST review accepts optional Reviewer. ActorSource distinguishes self-reported names from the local process user. This is not authentication.
Executor messages are sealed records RunInput, Candidate, Verdict, ReviewDecision and RunOutcome. Each exposes RunId, Sequence and CauseSequence and round-trips through default System.Text.Json. Payloads contain no Session references, delegates, streams or transport handles. No Service Bus package or transport abstraction is added.
The five-step registry interpreter remains intentionally restricted. DurableEvent v2 contains event plus typed artifact/status payload; snapshots are projections. Legacy snapshot-only runs are read-only archives. No actual checkpoint resume, general graph authoring or distributed coordination is claimed.
/api/info adds embedded gitRevision and actual loaded dllSha256. /api/runs/{id}/diagnostics partitions domain and raw framework arrival events. No qualification endpoint is added; message tests run in an external temporary console.
